# Project Management

Projects should be managed according to their importance, complexity, and risk.

## 1. Project definition

Every important project should answer:

- What are we trying to achieve?
- Why?
- What is the deadline?
- What is in scope?
- What is out of scope?
- How will success be measured?

## 2. Breakdown

Break projects into concrete tasks.

Each task should ideally have:

- Description.
- Owner.
- Deadline.
- Dependency.
- Expected output.
- Status.

## 3. Dependencies

Identify tasks that cannot start until other work is completed.

Critical dependencies should be visible.

## 4. Blockers

When progress stops, identify:

- The blocker.
- Who or what controls it.
- What can be done immediately.
- Whether escalation is necessary.

## 5. Status

Project status should communicate reality, not optimism.

Use clear states such as:

- Not started.
- In progress.
- Blocked.
- At risk.
- Completed.
- Cancelled.

## 6. Scope control

New requests should be evaluated against:

- Impact.
- Cost.
- Deadline.
- Existing priorities.

Do not allow uncontrolled scope expansion.

## 7. Completion

A project is complete only when:

- Deliverables are finished.
- Important validation is complete.
- The intended result is measured.
- Remaining risks are understood.
